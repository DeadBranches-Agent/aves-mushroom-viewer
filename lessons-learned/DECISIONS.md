# Aves fork — decision log

One-line summary: dated log of design decisions across every workstream in this fork (D1–D18 are the SFTP image source; D19–D22 the release APK workflow; D23+ the app identity), their reasons, and any later reversals.

Format: `D<n> (date) — decision — why — status`.

- D1 (2026-08-16) — Build the **libre** flavor for the deliverable APK — it is the F-Droid flavor with no Crashlytics and no GMS (`aves_useCrashlytics` only turns on for "play" tasks; `apply_flavor_libre.sh` pins `aves_services_none`) — adopted.
- D2 (2026-08-16) — Keep task-management docs in `lessons-learned/` inside the aves repo and commit them on the feature branch — the container is ephemeral; only pushed state survives across sessions — adopted.
- D3 (2026-08-16) — Use the fork `DeadBranches-Agent/dartssh2` as a git dependency on branch `claude/aves-sftp-image-source-4px7wz` (pushed unmodified) — task specifies dartssh2; its ranged reads and awaitable host-key callback cover all needs; no fork changes were required — adopted.
- D4 (2026-08-16) — Seam: new `EntryOrigins.sftp` + entries persisted in the local media DB under a **synthetic album path** (`<filesDir>/sftp/<host name>/…`), loaded by a `_loadSftpEntries` one-liner mirroring vaults — reuses `StoredAlbumFilter` grouping, read-only `canEdit`, and the whole collection layer without a new filter type (which needs ~7 registration sites) or a second `CollectionSource` — adopted.
- D5 (2026-08-16) — Serve full images, regions and sized thumbnails by **materializing original bytes to a cache file and re-issuing the platform op with the local `file://` URI** — Kotlin already handles files end-to-end (vault path); zero Kotlin decoding changes — adopted.
- D6 (2026-08-16) — **No WebP re-encode of thumbnails** (spec departure): embedded EXIF previews are cached as their original JPEG bytes (with an injected orientation APP1); thumbnails of fully-downloaded files come from the existing Glide pipeline and its disk cache — dart:ui cannot encode WebP, a Kotlin encode channel would duplicate Glide, and preview JPEGs are already thumbnail-sized — adopted.
- D7 (2026-08-16) — Embedded-preview shortcut is **JPEG-only in v1**; HEIC/AVIF/RAW and progressive/interlaced first-pass decoding are skipped, falling back to lowest-priority full download (which doubles as viewer warm-up) — JPEG is the dominant camera format; the other paths need per-container parsers/custom decoders with poor effort/benefit — adopted.
- D8 (2026-08-16) — Cache keys include host, remote path, mtime and size (per spec); byte requests that only carry a URI resolve the rest through an in-memory entry registry (`_entriesByUri`) fed by the DB loader and refresh — adopted.
- D9 (2026-08-16) — Commit the libre-flavor pubspec selection (`aves_services_none`, `aves_report_console`) on this branch — the branch targets a libre build and reproducibility across sessions matters more than keeping the repo's play-flavor default — **reversed by D13**.
- D10 (2026-08-16) — A remote file with changed mtime/size is handled as **remove + recreate** of its entry, so every mtime-keyed cache invalidates by construction — adopted.
- D11 (2026-08-16) — Entering the viewer suspends speculative grid prefetch on all hosts' schedulers (spec-faithful, simplest) — adopted.
- D12 (2026-08-16) — Phase-2 prefetch-window settings live in a self-contained `SftpPrefs` (shared preferences) with custom tiles, not in the app's `Settings` mixin machinery — avoids touching aves_model SettingKeys/defaults/store for two module-local ints — adopted.
- D13 (2026-08-17) — Restore the **play-flavor pubspec as the committed state** (reverses D9) — CI's `flutterw analyze` analyzes all plugin sources against the root workspace resolution; with libre committed, the excluded play plugins' Firebase/Google deps cannot resolve (58 errors, red on develop too). The excluded libre plugins only use packages already in the workspace graph, so play-committed analyzes clean (upstream convention). Flavor builds are unaffected: CI and local builds both run `scripts/apply_flavor_*.sh` first — adopted (PR #3).
- D14 (2026-08-17) — SFTP status errors and empty listings get **specific user-facing feedback**: `SftpStatusError` maps to "remote directory not found" / "permission denied" / server message instead of the generic "Failed"; a refresh that lists zero supported images warns instead of showing bare success (`refreshHost` returns the listed count). Driven by first-use test: three consecutive setup failures showed no reason — adopted (PR #3).
- D15 (2026-08-17) — **Discoverability**: the feature had zero UI surface until a host was configured *and* listed ≥1 image; first-use test showed six intuitive locations (drawer, Albums, Explore, home, bottom bar, navigation settings) with no trace. Fix in two parts: an SFTP drawer entry visible by default (removable like other drawer items), and configured hosts always shown as albums even when empty — adopted (discoverability branch).
- D16 (2026-08-17) — **SFTP delete happens entirely in Dart, before the platform delete op** — Kotlin's `ImageProviderFactory.getProvider` dispatches by URI scheme and returns null for `sftp://` (silent no-op), and the sftp design forbids adding sftp awareness to Kotlin. A `SftpEntryDeleteMixin` intercepts `EntryOrigins.sftp` entries at the top of both delete delegates (`_delete` in `entry_action_delegate.dart` and `entry_set_action_delegate.dart`, before any bin/`MoveType.toBin` routing, which would also silently no-op), confirms, calls `SftpMediaService.deleteEntries`, and reuses the `refreshHost` removal primitive (`_entriesByUri.remove` + `source.removeEntries`) — adopted (delete branch).
- D17 (2026-08-17) — **`deleteToRemoteTrash` defaults ON** — moving to `<host dir>/.trash` via SFTP `rename` is recoverable server-side, mirroring the app's own recycle bin defaulting on; permanent `remove` is the opt-out. `.trash` contents stay invisible to the app for free: listing is non-recursive and filters to regular files. Name collisions in `.trash` retry once with a deletion-timestamp suffix before the extension — adopted.
- D18 (2026-08-17) — **Delete confirmation always shows** (plain `showConfirmationDialog`, like host removal), instead of the skippable `ConfirmationDialog` machinery — avoids touching the upstream enum/settings for a fork-local action; the message names the actual behavior (permanent vs move to remote “.trash”). Aves' bin semantics (`settings.enableBin`) deliberately do not apply to sftp entries: the local bin cannot hold remote files — adopted.
- D19 (2026-08-21) — The release APK's version comes from the **latest `vMAJOR.MINOR` git tag** plus a `workflow_dispatch` `bump` input, with `versionCode = github.run_number` decoupled from `versionName` — no version file to drift and no commit-back to the branch; the tag doubles as the release record, and a monotonic run number cannot walk backwards when a major bump resets the minor — adopted (`lessons-learned/apk-release-versioning.md`).
- D20 (2026-08-21) — Pass the version into Gradle as **`ORG_GRADLE_PROJECT_verName` / `ORG_GRADLE_PROJECT_verCode` environment variables**, not `-P` flags — `flutter build` passes its own fixed `-P` set to Gradle and has no passthrough, but Gradle reads `ORG_GRADLE_PROJECT_*` from the environment as the same project properties — adopted.
- D21 (2026-08-21) — `defaultConfig`'s version fallback stays **`flutter.versionCode` / `flutter.versionName`** (the pubspec version) rather than the generic `"0.0-dev"` / `1` — every other build path in the repo (local, `debug-build.yml`, `release.yml`, the CodeQL profile build) passes no version property and must keep behaving exactly as before — adopted.
- D22 (2026-08-21) — The release workflow **pins `ref: develop`** — the task asked for "the main branch" but this repo has no `main`; `develop` is the trunk, and pinning it means the artifact is a trunk build regardless of which branch the run was dispatched from — adopted, revisit if a `main` branch is ever created.
- D23 (2026-08-21) — Ship the fork under its own **`applicationId = "viewer.mushroom.moo"`** and launcher name **"Mushroom Viewer"** — the shipped `libre` APK carried upstream's F-Droid identity (`deckers.thibault.aves.libre`, "Aves Libre") while being signed with this fork's key, which Android refuses to install beside or over an installed upstream build (the owner has upstream's GitHub `libre` build installed); `namespace` stays `deckers.thibault.aves`, since it is the source package, not the install identity — adopted (`lessons-learned/app-identity.md`).
- D24 (2026-08-21) — Drop the `libre` flavor's `applicationIdSuffix = ".libre"` so the shipped ID is exactly `viewer.mushroom.moo` — upstream needs that suffix only so its F-Droid build can coexist with its Play build; this fork builds `libre` alone (D1), and `appId` already separates it from everything upstream. Consequence: a local `play` build would now share the ID (and fail earlier anyway, on `google-services.json` client validation) — adopted.
- D25 (2026-08-21) — Pin the launcher label in a new `android/app/src/libre/AndroidManifest.xml` (literal + `tools:replace`), not only in the flavor's `values/strings.xml` — `app_name` is also defined in 56 locale-qualified `values-*` folders of `main`, which win at runtime for those locales, so the string override alone would show "Aves" on any non-default locale (upstream's own "Aves Libre" has this bug) — adopted.
